## 1. 현황 분석

### 현재 상태 (As-Is)

- 버터떡 맛집 정보가 인스타그램, 블로그, 커뮤니티에 분산되어 있음
- 통합 탐색 서비스가 없어 유저가 여러 플랫폼을 직접 검색해야 함
- 정보의 신뢰도와 최신성이 일정하지 않음

### 문제점 / 개선 기회

| 문제 | 개선 방향 |
|------|---------|
| 맛집 정보가 흩어져 있음 | 한 곳에 모아 지도로 시각화 |
| 검색 결과의 신뢰도가 낮음 | 운영진 검수 + 유저 제보 병행 |
| 저장/공유 기능 없음 | 즐겨찾기로 나만의 리스트 관리 |

---

## 2. 목표 (To-Be)

MZ세대가 버터떡 맛집을 지도에서 탐색하고, 마음에 드는 곳을 저장해 다시 방문할 수 있는 웹 서비스를 1개월 내 MVP로 출시한다.

---

## 3. 솔루션

### 접근 방식
- 지도 API 기반으로 맛집 위치를 핀으로 시각화
- 운영진이 초기 데이터를 직접 입력하고, 유저 제보로 점진적 확장
- 즐겨찾기 기능으로 재방문 및 재탐색 동선 확보

### 핵심 아이디어

> "버터떡 맛집 정보를 검색 대신 지도에서 발견한다"

- 지도 탐색 중심의 UX (검색보다 둘러보기)
- 핀 클릭 한 번으로 상세 정보 바로 확인
- 하트(즐겨찾기) 버튼으로 저장까지 최소 동선

## 5. 예외 처리 / 엣지 케이스

| 상황 | 처리 방식 |
|------|---------|
| 등록된 맛집이 없는 지역 검색 | "아직 등록된 맛집이 없어요. 첫 번째로 등록해보세요!" 메시지 + 등록 유도 버튼 |
| 유저 제보 맛집 검토 전 | 지도에 미표시, 운영진 검토 후 노출 |
| 맛집 사진 미등록 | 기본 플레이스홀더 이미지 표시 |
| 영업 종료 / 폐업 맛집 | 제보 기능으로 수정 요청 가능, 운영진이 상태 업데이트 |
| 지도 API 로딩 실패 | "지도를 불러오지 못했어요. 잠시 후 다시 시도해주세요" 안내 |
| 즐겨찾기 (로그인 미결정) | 로그인 없이 로컬 저장 우선 적용 → 추후 계정 연동 |
